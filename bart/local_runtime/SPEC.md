# `bart.local_runtime` — Spec

> **Audience:** future contributors (humans and agents) who need to extend, debug, or replace the local-model stack without re-reading every line of code.
>
> **Status:** authoritative. The code follows this spec; if they disagree, the spec is the bug.

## 1. Mission

Bart's promise to the user is: type `./run`, get a study packet. The local runtime extends that promise to users without an Anthropic key or subscription: type `./run`, get a study packet generated by an open-weight model on your own hardware. **No `pip install`, no model download instructions, no model-server commands, no debugging.** Bart does it all, automatically, with clear messages when something goes wrong.

The runtime is the layer that makes that real:

1. **Detect** what hardware the user has.
2. **Choose** the best open-weight model that fits.
3. **Install** the inference engine.
4. **Download** the weights.
5. **Serve** the model via OpenAI-compatible HTTP.
6. **Speak** that protocol from `LocalBackend` (in `bart/backends.py`).
7. **Clean up** at end-of-run.

Each of those is one Python module under `bart/local_runtime/`.

## 2. Module Map

| Module | Single responsibility |
|---|---|
| `hardware.py` | Detect platform, RAM/VRAM, accelerator. Recommend a tier. **No I/O beyond OS probes.** |
| `models.py` | Static catalog of supported (model × format × quant) entries. **Pure data + a picker.** |
| `cache.py` | On-disk weight cache: layout, freshness, eviction, purge. **Filesystem only.** |
| `installer.py` | Install the engine pip package. Validate HF repo. Download weights. **The only network egress.** |
| `server.py` | Manage the inference subprocess. Wait for healthcheck. atexit cleanup. **The only subprocess management.** |
| `client.py` | OpenAI-compatible HTTP client. Streaming, retry, heartbeat, JSON via grammar. **The only HTTP traffic to localhost.** |
| `grammar.py` | JSON-Schema → GBNF compiler. **Pure function.** |
| `handle.py` | `prepare()` ties everything together. **The only public bring-up point.** |
| `errors.py` | `LocalRuntimeError(code, message, hint)`. **The only exception type that escapes to users.** |

If you find yourself adding network code to `server.py` or subprocess code to `client.py`, you're violating the boundaries — split your change instead.

## 3. Public API

The orchestrator only ever calls into:

```python
from bart.local_runtime import prepare, RuntimeHandle

handle = prepare(console=..., model_key=None, on_event=cb)
# handle.client       LocalClient (OpenAI-compatible)
# handle.model        Model (catalog entry)
# handle.platform     Platform (detected hardware)
# handle.context_window  effective n_ctx the server was started with
# handle.parallel_slots  how many concurrent requests the server can serve

handle.shutdown()  # idempotent; called from a `finally` block
```

`bart.backends.LocalBackend(runtime=handle, ...)` adapts that handle to the same `complete()` protocol as `AnthropicAPIBackend` so the agents stay backend-agnostic.

**Nothing else** in `bart.local_runtime` is API. The submodules are implementation details and can be refactored without warning.

## 4. Invariants

These are pinned by tests in `tests/test_local_runtime*.py`. Don't break them.

1. **Apple Silicon prefers MLX.** `pick(p, tier, family)` returns an MLX entry on Apple Silicon when one exists at that tier; otherwise a GGUF entry.
2. **Non-Apple never gets MLX.** `pick(p, tier, family)` never returns an MLX entry on a non-Apple platform.
3. **System role passes through.** `LocalBackend.complete(system="...")` sends `{"role":"system","content":"..."}` as the first message. (This is the audit-bug-#1 anchor.)
4. **`max_tokens` is capped against `n_ctx`.** The client never asks the server to generate more tokens than fit in the remaining context window. (Audit-bug-#2 anchor.)
5. **Retry on 5xx and network errors, fail fast on 4xx.** The client retries up to 4 times with exponential backoff; honors `Retry-After` headers; never retries 4xx. (Audit-bug-#3 anchor.)
6. **JSON mode + schema → grammar.** When `response_format="json"` AND `is_llama_cpp=True` AND a schema is provided, the request includes a `grammar` field. (Audit-bug-#5 anchor.)
7. **Server slot count caps `max_parallel`.** The orchestrator must not submit more concurrent calls than `handle.parallel_slots`. (Audit-bug-#6 anchor.)
8. **Every user-visible failure is a `LocalRuntimeError`.** Stack traces never reach the user; they go to the run log only.
9. **Resumable downloads.** A network failure mid-download leaves the partial files on disk; the next `ensure_weights()` call resumes via HTTP Range.
10. **Weights are never re-downloaded within 24h.** The cache TTL is 24h; touching on shutdown extends it to a full day from last use.
11. **The server stops when `shutdown()` is called.** Including via `atexit` if the orchestrator is killed by SIGINT/SIGTERM.
12. **Family routing is opt-in.** `pick(p, tier)` and `pick(p, tier, family="auto")` resolve to the default family (Qwen3). Gemma 4 is only returned when `family="gemma4"` is requested explicitly (config `local_model_family`, or `--model gemma` from the website).

## 5. Error taxonomy

`LocalRuntimeError.code` is a stable identifier. Tests pin behavior to codes; future GUI surfaces can route by code. Adding a new code is fine; **renaming an existing one is a breaking change**.

| Code | Trigger | User remediation |
|---|---|---|
| `DISK_FULL` | <10% headroom for the chosen model | Free space or set `BART_CACHE_DIR` |
| `NETWORK` | DNS / TCP / SSL / timeout during download | Re-run; resumes |
| `HF_REPO_MISSING` | Sentinel-file HEAD returns 404 | Update catalog or pick a different model |
| `HF_GATED` | HEAD returns 401/403 | Set `HUGGING_FACE_HUB_TOKEN` or pick non-gated |
| `PIP_INSTALL` | `pip install` returned non-zero | Install by hand with shown command |
| `ENGINE_IMPORT` | Engine installed but `import` fails | Wipe `.venv` and re-run |
| `SERVER_START` | Server subprocess exited before healthcheck | Probably OOM; pick a smaller model |
| `SERVER_HEALTH` | Server didn't answer `/v1/models` within 180s | Probably stuck loading; pick a smaller model |
| `WEIGHTS_INCOMPLETE` | Files missing post-download | `./run cleanup` then re-run |
| `CACHE_PERMISSION` | Cannot write to cache dir | Fix permissions or set `BART_CACHE_DIR` |
| `HARDWARE_INSUFFICIENT` | Even tiniest model won't fit | Use API or subscription mode |

## 6. Catalog Policy

`models.py` is curated, not generated. The catalog is grouped by **family**
(`Model.family`): Qwen3 is the default family; Gemma 4 is an opt-in family.
To add a model:

1. **License must allow free local use.** Apache 2.0, MIT, or the explicit Llama / Gemma terms.
2. **Public repos are the default; gated repos must be opt-in.** A gated family (e.g. Gemma 4, which Hugging Face gates behind licence acceptance) must never be reachable from `pick(..., family="auto")` — only from an explicit `family=` request. The `HF_GATED` error path tells the user to set `HUGGING_FACE_HUB_TOKEN`.
3. **Weights must be quantized to 4-bit.** Q5/Q6/Q8 are user upgrades, not defaults.
4. **For each model, ship both an MLX entry and a GGUF entry** so the picker has a viable choice on every platform.
5. **`bytes_on_disk` is a precheck only.** Don't tune it tight — `ensure_weights()` pads by 10% + 1 GB workspace.
6. **`min_usable_gb` is the gate.** Set it to "comfortably fits Q4 plus 32K KV cache plus OS overhead." A 4 GB model with 32K context wants `min_usable_gb >= 7`.
7. **Add the same key to `bart/telemetry.py` PRICING with all-zero entries.** Otherwise `record()` returns 0.0 anyway, but consistency matters.
8. **Add a row to the family's tier table** (`_QWEN3_TIER_ORDER` / `_GEMMA4_TIER_ORDER`, registered in `_FAMILY_TIER_ORDER`). The picker is dumb on purpose — the table is the truth.

## 7. Engine selection

```
darwin/arm64           → mlx-lm   (Apple Silicon native; ~2× faster than llama.cpp Metal)
linux/cuda  (≥4 GB VRAM) → llama-cpp-python[server]  (CUDA wheels)
linux/cpu, windows, intel-mac → llama-cpp-python[server]  (CPU wheels)
```

The choice is final at `prepare()` time. If a user wants to override (e.g. force CPU on a Mac), expose it as `BART_FORCE_ENGINE=...` later — don't put it in the catalog.

## 8. Concurrency

- **mlx-lm: 1 slot.** It serializes requests internally.
- **llama-cpp-python: 1 slot by default**, configurable. We don't bump it because multi-slot KV-cache memory isn't worth the multi-user complexity for a single-user CLI.

The orchestrator must read `handle.parallel_slots` and cap `max_parallel`. There's a watchdog test for this.

## 9. Lifecycle

```
./run
  ├─ bash bootstraps .venv + pip install -r requirements.txt
  └─ python -m bart …
       ├─ load_config() / run_setup_wizard()
       │     └─ if auth_mode == "local":
       │           detect → tier → pick model → save model_key
       └─ Orchestrator.run()
             ├─ if auth_mode == "local":
             │     handle = prepare(...)        # install + download + start server
             │     llm = LocalBackend(handle)
             ├─ … pipeline …
             └─ finally:
                   handle.shutdown()           # SIGTERM, then SIGKILL after 5s
                   touch(model)                # extend 24h cache
```

`atexit` registers `handle.shutdown()` as a backup so SIGKILL of the parent still kills the server. Don't add a SIGINT handler — Python's default is fine and our `finally` cleans up.

## 10. Extension points

If you're adding a feature, here's the right place:

| Want to add | Edit |
|---|---|
| A new model | `models.py` — add Model entry + tier mapping. |
| A new engine | `installer.py` (engine_package), `server.py` (start cmd). Probably justify a separate spec section. |
| A new platform | `hardware.py` — extend `detect()` + `recommended_tier()`. Add catalog entries with the right `format`. |
| A new JSON Schema feature | `grammar.py` — add a branch in `compile_node`, add a test in `tests/test_local_runtime.py`. |
| A new error class | `errors.py` — add a new code. Add a translation in installer/server/client to that code. Update this spec's table. |
| A new doctor check | `bart/commands.py:doctor()` — add a step that runs in <2s and prints pass/fail + hint. |

## 11. Testing strategy

Two layers:

**Unit (`tests/test_local_runtime.py`)** — pure logic. Fast (≤2s total). No subprocesses, no HTTP, no FS beyond `tmp_path`.

**Wiring (`tests/test_local_backend_wiring.py`)** — stand up a stub HTTP server that mimics the OpenAI streaming contract. Exercises `LocalBackend → LocalClient → server` end-to-end without real model weights.

**Harness (`tests/test_local_runtime_harness.py`)** — black-box invariant tests. Each numbered invariant in §4 has at least one test.

**No integration tests in CI** — the real download is too slow. There's a `./run doctor` command for users to validate their machine, and an off-CI `tests/integration/` script for developers.

## 12. Performance targets

(M2 Pro, 32 GB unified, Qwen3-4B MLX 4-bit; representative numbers, not contractual)

- Cold pip install + model download: 3-5 min one-time
- Server cold start: 5-12 s
- First-token latency: 0.3-0.8 s
- Sustained generation: 80-130 tok/s
- Daily-lesson generation (5K input + 4K output): ≤90 s

If a change pushes any of these >2× worse, the change needs justification.

## 13. Anti-goals

We do **not** support:
- Multi-user serving (one CLI user at a time)
- Network-served local models (no remote llama-server, no http://other-host)
- Per-call model swapping (one model per `prepare()` call; restart for a new one)
- Streaming to multiple clients
- Hot-reloading weights

These are all worth saying out loud because they're the second-order requests that creep in. We say no — Bart is a single-user CLI for one user studying one subject, and the runtime is shaped for that.
